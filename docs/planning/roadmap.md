# 后续路线图

本文只列尚未完成的开发与验收工作，不表示现有 API。已实现能力见 [项目 README](../../README.md)、[源码地图](../development/code-map.md) 和 [学习路线](../development/learning-guide.md)；后续改动遵守 [架构约束](../design/architecture.md)。阶段按依赖推进，不预设发布日期。

## 优先级

| 阶段 | 目标 | 完成条件 |
| --- | --- | --- |
| P0 | 取得真实平台与服务器运行证据 | 收发、恢复、停止、数据保护和持续运行可复现 |
| P1 | 从配置组合本地扩展 | 可独立启停，依赖明确，安装失败可回滚或报告残留 |
| P2 | 提供可组合业务示例与 Adapter 契约 | 业务复用现有两种接入，新事件源可复用契约测试 |
| P3 | 提供开发者诊断与性能回归方法 | 从配置追踪到注册和执行，不破坏懒解析与有界状态 |

## P0：实机验收

自动化测试已有本机 HTTP/WebSocket、模拟扫码、发布物和进程行为覆盖；真实账号和长期服务器运行仍需独立验证。验收步骤见 [部署说明](../guides/deployment.md#实机验收)。

- 确认当前提交在现有 Linux/Windows CI 矩阵通过；实测 Windows 首次和再次 Ctrl+C、启动中取消及退出后的进程残留。
- 在 Linux 上从其他工作目录通过 screen 启动，检查凭据和备份权限、停止信号与默认 45 秒停止上限。
- 使用真实 NapCat 检查回复、断线重连、过载时控制帧处理及 drain 期间已接纳事件的回复。
- 使用真实 QQ 官 Bot 检查扫码与凭据复用、群与 C2C 私聊、权限失败、恢复与停止。
- 实机覆盖更新和回滚，逐字节比较配置、凭据与业务文件，检查历史日志保留。
- 连续运行至少 24 小时，记录版本、环境、消息负载、资源、重连与退出结果。

**验收：**取得可复现的操作与脱敏结果，修复阻断启动、数据保留或正常停止的问题。执行结果随对应版本的发布记录保存；尚未取得的真实平台结果明确标为未验证。

## P1：通过配置组合扩展

目前 [应用](../../application.py) 通过 [hooks/__init__.py](../../hooks/__init__.py) 固定注册业务。下一步在应用层建立显式扩展注册表，以稳定 ID 选择本地功能，保留直接注册 Hook 的入口。

1. TOML 声明启用项和各自配置，先采用单层配置；普通启动只读已有文件。
2. 每个扩展取得独立 Scope，注册 Hook、Provider、Service 和生命周期资源；现有业务逻辑继续复用。
3. 在连接平台前完成配置校验、依赖排序与安装。共用同一 Field/ServiceKey 实例，扩展 ID 不改变键的身份语义。
4. 安装失败撤销本次已安装项；取消或清理受阻时保留必要资源并报告原因。
5. 提供只读组合说明，列出启用项、来源、脱敏配置、Scope 与声明依赖。

**验收：**配置启停 `ping` 无需修改应用入口；停用命令扩展时不注册其字段。未知或重复 ID、错误配置、依赖缺失或循环提前报错。同一配置产生确定组合，服务归属唯一，安装失败可回滚。独立 `Bot()` 不扫描扩展、不读取配置、不创建目录或导入可选依赖。配置节名及注册签名在实现时确定。

## P2：业务示例与接入契约

### 可选业务扩展

使用 P1 的注册方式，提供默认停用的权限、限流与持久化示例。

| 示例 | 最小范围 | 验收 |
| --- | --- | --- |
| 权限 | Hook 与共享 Field 表达用户/会话规则，异步查询通过 Service | 判断顺序与默认规则明确，拒绝时不进入后续业务 |
| 限流 | Scope 拥有的 Service 保存有界、可过期状态 | 可组合运行，状态容量和过期策略明确，停用后清理资源 |
| 业务持久化 | Service 与 `APP_PATHS.storage` 保存带格式版本的业务数据 | 重启恢复、损坏处理、覆盖更新均可验证，提供完整学习步骤 |

同一业务在 OneBot 与 QQ 官 Bot 上使用共享字段；安装失败和卸载也需要验证。业务限流与 Scheduler 容量分别配置，数据库依赖保持可选，示例不将事件队列改为持久队列。

### Adapter 契约

- 明确路由类型、会话键、就绪状态、回复能力与不支持的场景。
- 提炼事件夹具，验证 raw 保留、懒字段、缺失语义及 Provider 注册/撤销。
- 验证过载、断线、重连、启动失败和关闭；确认、去重与丢弃策略由各协议说明。
- 提供自定义事件源的完整示例，复用现有 Bot 与 Client 接口。

**验收：**现有 OneBot、QQ 官 Bot 和示例事件源通过适用的同一组契约；未读取的业务字段不解析。新增平台不要求核心增加平台分支或全量统一消息对象。

## P3：诊断与性能回归

- 用公开只读视图说明 Hook 顺序、过滤条件、Field/Service 依赖和资源归属。
- 将配置启用项与实际注册对应起来；诊断不连接平台、不执行 Provider、不展示凭据。
- 显式启用 Trace 时，解释事件命中、跳过、停止或失败；范围和采样有界，默认关闭。
- 为扩展数量、会话积压、慢 Hook 和诊断开关建立可复测基线，说明输入、环境与统计方法。
- 为完整扩展示例同步补充源码导航、可运行示例、依赖和 API 迁移说明。

**验收：**从配置可追踪到注册来源和执行结果。默认诊断不保存原始消息或增加网络 I/O。性能回归在同一环境重复测量并分析，不将历史本机数字作为跨机器固定门槛。

## 有需求后再启动的方向

| 方向 | 启动条件与边界 |
| --- | --- |
| Webhook 或其他协议 | 有真实部署需求与联调环境；新增 Adapter，定义鉴权、确认、重试与过载语义 |
| 多账号、多 Adapter | 单账号确实限制业务；账号、凭据、连接、会话键与回复归属隔离 |
| 离线录制与重放 | 手工夹具难以复现问题；显式启用、脱敏、有保留上限，假 Client 阻止真实发送 |
| 扩展热替换 | 停机更新无法满足需求；先定义在途工作、共享依赖和失败恢复 |
| 跨重启事件恢复 | 明确需要补发或审计；先定义投递、幂等与存储迁移语义 |
| AI、群管等业务 | 有具体场景与接口；作为普通 Hook/Service 扩展，依赖按需安装 |

插件市场、Web 管理后台、复杂配置叠加和完整平台 API 封装当前没有排期。

## 维护规则

交付后从路线图删除已完成事项，将现有行为写入使用与开发文档；代码实现完成而实机证据缺失时，只保留验收任务。新增目标需要说明问题、职责层与成功标准，遵守 raw、懒解析、同步 Provider、资源归属和有界调度约束。历史过程由提交与版本发布记录保存。
