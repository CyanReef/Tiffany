## 前后实测

采样时间为 **2026-10-05 00:21–00:25，UTC+8**。Windows、CPython 3.14.4、ProactorEventLoop，同一解释器与依赖环境；7 轮交替前后版本，每版每轮一个独立子进程。每场景预热 200 个事件，再测量 2,000 个，GC 和真实指标开启，Trace 关闭。

| 场景 | 吞吐：前 → 后（事件/秒） | 吞吐变化 | P95：前 → 后 |
| --- | ---: | ---: | ---: |
| 1 个 Hook，直接 `Bot.emit` | 15,602 → 15,416 | −1.2% | 70.11 → 71.21 µs |
| 10 个 Hook | 8,920 → 9,308 | +4.4% | 154.81 → 120.21 µs |
| 1 个匹配 + 1,000 个无关 Hook | 15,156 → 15,532 | +2.5% | 79.12 → 71.60 µs |
| OneBot 接纳到 Hook 完成 | 10,193 → 14,707 | **+44.3%** | **111.61 → 74.20 µs** |
| 模拟 I/O，4 并发 | 262.6 → 263.1 | +0.2% | 62.142 → 62.118 ms |
| 模拟 I/O，16 并发 | 1,050.3 → 1,052.5 | +0.2% | 15.996 → 16.001 ms |

表中均为七轮中位数。直接核心路径与模拟 I/O 的吞吐变化较小；十 Hook 的延迟波动较大，不将这批差异解释为额外核心提速。主要可解释收益来自消除 OneBot 每事件的重复反射。OneBot 接纳场景的平均每事件耗时降低约 30.7%，P95 降低约 33.5%。

OneBot 场景创建原始 OneBot 字典及 Envelope，经过适配器 `_emit()`、实际 Runtime 接纳和调度、懒字段解析及 Hook；等待事件完成后才停止计时。不包括 WebSocket 收包、JSON 解码、平台回复或 LLM。I/O 场景使用 16 个会话，每个 Hook 等待 5 ms；Windows 实际定时器延迟以实测为准。这些是离线闭环负载，不能外推线上吞吐。

单 Hook 预热后工作集中位数为 35.99 → 36.03 MiB，OneBot 场景为 41.99 → 42.17 MiB；同一子进程内多个场景共享解释器分配历史，RSS 只能作为本批组件工作集参考。内存改动的主要证据是引用释放与字典容量检查。

[完整采样、分位数、各轮范围与逐文件源码指纹](../../benchmarks/results/archive/optimization/code-audit-20261005.json) 保留在仓库。共享核心指纹分别为 `4603f36949bdad4adeedcacde74eca44374237bc2946050f9f15ad5bb4ed90d0` 和 `bdaec54c3709d837fc4302a4fe10cd236429959a6c215aa99f594efc1f706773`。该共享指纹不包含 OneBot 接纳适配器；JSON 的 `source_manifests` 另保存两版全部 71 个快照源文件的 SHA-256，包括适配器与测量器。清单在采样后从前后快照补入，并确认候选文件及测量器与采样时一致。

## 复测

本工作区的 `.build-cache/audit-20261005/before/` 与 `after/` 保存本轮前后源码和 SHA-256 清单，不进入发布包。使用已有的隔离对比环境执行，psutil 只用于测量，不进入核心依赖：

```powershell
python -B -m benchmarks.optimize --baseline .build-cache/audit-20261005/before --candidate .build-cache/audit-20261005/after --events 2000 --warmup 200 --repeats 7 --output .build-cache/audit-20261005/recheck.json
```

新一轮改动前可通过 `python -B -m benchmarks.optimize --snapshot <新路径>` 保存基线。`--cases onebot_admission` 可单独检查适配器接纳；其他默认场景仍校验处理器调用、字符数、真实指标和关闭后的 owner 清理。
